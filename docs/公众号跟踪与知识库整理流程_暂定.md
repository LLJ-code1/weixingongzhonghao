# 公众号跟踪与知识库整理流程（暂定）

## 目标

这个流程不是为了把公众号文章简单做成摘要，而是为了完成三件事：

- 每天知道新增了哪些内容。
- 把值得看的文章整理成可直接使用的观点。
- 从长期关注的公众号中沉淀分析框架，逐步形成知识库。

当前阶段先采用手动确认流程，不直接做全自动化。

## 基本原则

- 先分流，再整理，不默认每篇文章都深度处理。
- 先看内容用途，不按公众号固定归类。
- 每篇文章可以有一个主分类，再加多个标签。
- 分类是开放的，后续关注新公众号后可以继续扩展。
- 每一步执行前先说明要做什么，经确认后再进入下一步。

## 每日流程

### 1. 更新与抓取

先触发本地公众号服务更新，获取本次新增文章。

本阶段只关注新增文章，不默认重新处理历史文章。

### 2. 生成今日文章池

今日文章池只做基础信息整理：

- 公众号名称
- 文章标题
- 发布时间
- 链接
- 主分类
- 标签
- 建议处理深度
- 处理状态

这一步的目标是先看清今天来了什么，不急着写观点。

### 3. 文章分流

按照内容用途做主分类。主分类用于决定文章放在哪里，标签用于后续检索。

#### 基础分类

1. 宏观与政策
   - 经济数据、财政、货币、利率、通胀、出口、PMI、政治局会议、央行。

2. 市场交易与资金面
   - 指数、仓位、CTA、资金流、风险偏好、估值、利率交易、短期市场波动。

3. 美股与海外资产
   - 美股科技、海外财报、美元、美债、海外央行、全球风险资产。

4. AI与科技主线
   - AI资本开支、云厂商、算力、模型、Agent、芯片、数据中心、电力。

5. 行业与产业趋势
   - 储能、光模块、半导体、创新药、消费、地产、汽车、机器人等。

6. 公司与商业模式案例
   - 单家公司财报、战略变化、估值重估、竞争格局、商业模式拆解。

7. 投资方法与研究框架
   - 分析方法、估值方法、周期判断、组合思路、交易纪律、研究框架。

8. 个人知识与非投资内容
   - 效率工具、AI工具、写作方法、读书、职业、生活类内容。

9. 待分类
   - 一时判断不清、需要人工确认、或者后续再归类的内容。

#### 标签规则

标签解决“以后怎么找”，可以比主分类更细。

示例：

```text
主分类：AI与科技主线
标签：#AI资本开支 #云厂商 #美股科技 #现金流
```

```text
主分类：宏观与政策
标签：#PMI #外需 #价格 #库存 #政策观察
```

```text
主分类：个人知识与非投资内容
标签：#效率工具 #知识管理 #AI工作流
```

## 处理深度

不同文章采用不同处理深度，避免把知识库变成信息堆积。

### 深度整理

适用内容：

- 宏观核心文章。
- 重要政策解读。
- 重要市场框架。
- AI资本开支、算力链、美股科技主线中的关键文章。
- 明显可以沉淀分析框架的文章。

输出：

- 整理后的观点。
- 可直接使用的一句话。
- 分析框架抽取。
- 后续跟踪变量。

### 中等整理

适用内容：

- 市场交易与资金面。
- 美股与海外资产中的普通主线文章。
- 公司案例中对估值、商业模式、竞争格局有启发的文章。

输出：

- 核心观点。
- 标题 + 简述。
- 对市场或投资判断的含义。

### 轻量记录

适用内容：

- 行业与产业趋势中的候选主题。
- 暂时没有形成框架，但可能后续有用的内容。
- 非投资内容中可能有工具或方法价值的文章。

输出：

- 标题。
- 简短说明。
- 标签。
- 后续是否需要复看。

### 暂不处理

适用内容：

- 营销内容。
- 重复信息。
- 纯资讯快讯。
- 与当前关注方向无关，且没有框架价值的内容。

输出：

- 可只记录在文章池中，也可以直接跳过。

## 单篇文章整理模板

### 核心观点

用一段话说明文章真正想表达的判断。

### 标题 + 简述

用多个小标题拆解文章观点。每个小标题后写一段简述。

示例：

```text
1. 经济仍在修复，但动能没有继续加速
制造业仍在扩张区间，说明经济没有掉头向下。但PMI较上月小幅回落，反映前期快速修复后，边际动能开始放缓。
```

### 可直接用的一句话

把文章压缩成一句可以用于复盘、汇报、笔记或投研判断的话。

## 分析框架抽取模板

只有值得沉淀的文章才需要做这一步。

### 文章使用的分析变量

记录文章用哪些变量解释问题。

示例：

```text
PMI分析：生产、需求、价格、库存、企业结构、非制造业。
出口分析：外需量、中国份额、出口价格。
```

### 文章的因果链

记录文章如何从现象推导到结论。

示例：

```text
中东局势 -> 油价和化工成本上升 -> PPI压力加大 -> 企业利润被挤压 -> 政策空间和市场预期受影响。
```

### 后续跟踪变量

记录后面要看哪些数据验证观点。

示例：

```text
PMI新订单、新出口订单、原材料价格、出厂价格、原材料库存、建筑业商务活动指数。
```

### 可复用框架

如果这篇文章形成了可复用框架，就沉淀成一句结构化表达。

示例：

```text
出口 = 外需量 × 中国份额 × 出口价格
```

## 每日输出建议

每天最多保留三类输出。

### 今日文章池

记录新增文章和分流结果。

### 今日观点整理

只放已经整理过、值得看的文章观点。

### 分析框架增量

只记录今天新增或强化的框架。

示例：

```text
新增框架：出口三因素框架
来源文章：华泰 | 固收：地缘扰动下的出口三问
框架表达：出口 = 外需量 × 中国份额 × 出口价格
```

## 与知识库的关系

后续如果接入 LifeOS 或其他知识库，建议分三层沉淀：

### Source 层

保留单篇文章来源、链接、整理后观点。

### Knowledge 层

沉淀可复用分析框架、变量、因果链、判断方法。

### Application 层

保留可以用于日报、周报、PPT、投资复盘、客户转述的话术和观点。

## 执行规则

- 当前流程先手动跑通，不直接做自动化。
- 每次执行前先说明下一步要做什么。
- 用户确认“可以”后再继续。
- 不默认只处理固定公众号，以当前订阅列表和新增文章为准。
- 不默认每篇文章都深度整理，先分类，再决定处理深度。
- 如果分类不确定，先放入“待分类”，不要硬归类。

## 当前待验证

- 今日新增文章池的格式是否够用。
- 单篇文章整理模板是否适合不同类型内容。
- 分析框架抽取是否能稳定沉淀为知识库条目。
- 哪些分类需要继续扩展或合并。
